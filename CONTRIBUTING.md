# Contributing

1. Open an issue describing the operational problem and the acceptance criteria.
2. Create a focused branch from `main`.
3. Keep configuration examples sanitized; never commit credentials, private endpoints, or local paths.
4. Open a pull request with risk, rollback, and verification notes.
5. Wait for CI and review before merging.
6. Tag user-visible infrastructure milestones with a release.

Infrastructure changes should be small, reversible, and documented at the boundary they affect.
